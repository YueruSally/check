# 研究结果数据说明

这份说明用于快速理解项目中的结果数据。它不采用论文写法，主要说明每个目录和文件的用途、各轮实验解决了什么问题，以及读取结果时需要注意的统计口径。

## 1. 这组研究结果回答什么问题

研究关注中美多式联运网络在西海岸港口中断后的货流调整。三个美国内陆目的地分别是：

| 案例 | 内陆目的地 |
| --- | --- |
| D1 | Chicago，芝加哥 |
| D2 | Memphis，孟菲斯 |
| D3 | Columbus，哥伦布 |

可选的美国门户包括洛杉矶/长滩、西雅图/塔科马和纽约/新泽西。模型同时最小化总运营成本和货量加权平均交付时间。纽约/新泽西份额是模型求解后观察到的网络结果，不是优化目标。

本文把纽约/新泽西承担至少10%的网络总货量作为“具有运营意义的替代门户”判据。这个网络层面的10%判据与模型中的最小路径份额约束不同。模型约束要求某个货物批次启用一条路径时，该路径至少承担该批次10%的需求。

## 2. 最主要的结果

| 研究内容 | 结果 |
| --- | --- |
| 基准门户结构 | D1、D2和D3均不使用纽约/新泽西，货物全部经两个西海岸门户运输。 |
| 单独降低容量 | 西海岸剩余容量为70%、67.5%、65%或60%时，纽约/新泽西份额均为零。单独将任一西海岸门户容量降至50%也未激活纽约/新泽西。 |
| 普通延误 | 96和120小时延误未产生纽约/新泽西货量。168小时延误只在D2和D3产生很小的正份额，仍远低于10%。 |
| D1独立延误区间 | 264小时的平均份额为6.59%，288小时为39.00%，因此测试激活区间为264至288小时。 |
| D2独立延误区间 | 240小时的平均份额为1.24%，264小时为19.28%，因此测试激活区间为240至264小时。 |
| D3独立延误区间 | 168小时仍低于1.2%，240小时平均份额为26.14%，因此测试激活区间为168至240小时。 |
| D1复合中断区间 | 在延误168小时的条件下，剩余容量35%时所有解均低于10%，剩余容量30%时所有解均高于10%。测试区间为35%至30%剩余容量。 |
| D2复合中断 | 35%剩余容量时，份额范围为6.88%至16.97%。结果跨越10%，且30%、35%和40%三个容量点的均值不单调，因此只能解释为过渡区域。 |
| NY/NJ反事实价值 | 允许和禁止NY/NJ的场景均保持30/30次可行。NY/NJ改善部分严重中断下的成本—时间可达到前沿，但不是维持可行性的必要条件，也不能恢复基准表现。 |
| 随机种子稳定性 | 严重中断和区间细化场景中，成本和交付时间的30个同种子配对差值方向一致。配对检验支持这两个指标的变化具有稳定性。 |

## 3. 数据目录的整体结构

项目中与结果解释直接相关的内容分为三层：

```text
results/        每次优化运行及非支配解的原始输出
analysis/       从 results/ 整理出的场景效应、门户份额和配对统计
paper/figures/  使用已保存结果绘制的论文图件
```

通常不需要从最底层文件开始读取。如果只是了解结论，先看 `analysis/`。如果需要追踪某个数值或具体运输方案，再进入对应的 `results/` 目录。

## 4. 每轮实验的用途

每轮场景实验都有自己的基准运行。场景比较必须使用同一版本目录中的基准，不能从其他版本随意选取基准。

| 目录 | 规模 | 用途 | 是否作为当前论文主要证据 |
| --- | ---: | --- | --- |
| `results/baseline_30seeds/` | 3个案例 × 30个种子 | 早期基准和计算预算校准，每次运行1,968次评价。 | 否 |
| `results/nsga2_final_30seeds/` | 3个案例 × 30个种子 | 将计算预算提高至每次运行4,800次评价后的基准校准。 | 主要用于校准记录 |
| `results/v04_baseline_30seeds/` | 3个案例 × 30个种子 | 加入每条启用路径至少承担批次需求10%的运营规则后，重新建立基准。 | 用于确认约束后的基准结构 |
| `results/v05_noncarbon_scenarios_30seeds/` | 9个场景 × 3个案例 × 30个种子，共810次运行 | 初步筛选容量、延误和复合中断，确定后续阈值实验方向。 | 辅助证据 |
| `results/v06_threshold_scenarios_30seeds/` | 12个场景 × 3个案例 × 30个种子，共1,080次运行 | 测试中等容量下降、单一门户中断，以及96至168小时区域延误。 | 是 |
| `results/v07_activation_scenarios_30seeds/` | 6个场景 × 3个案例 × 30个种子，共540次运行 | 测试240和336小时延误，以及剩余容量30%或40%并叠加168小时延误的严重场景。 | 是 |
| `results/v08_focused_activation_thresholds_30seeds/` | 5个场景 × 2个案例 × 30个种子，共300次运行 | 用264、288和312小时延误细化D1、D2的独立延误区间，并测试35%剩余容量的复合场景。 | 是 |

v08只包含D1和D2。D3在240小时延误时已经稳定超过10%，所以没有继续测试264、288和312小时。D3也没有重复测试35%剩余容量的复合场景。

## 5. `results/` 中各文件的作用

每个正式结果目录通常包含以下文件。

### `manifest.json`

这是该轮实验的说明文件，应当最先读取。它记录：

| 内容 | 用途 |
| --- | --- |
| `cases` | 本轮包含哪些目的地案例 |
| `scenarios` | 本轮包含哪些场景 |
| `seeds` | 30个随机种子的完整列表 |
| `algorithm` | 种群规模、代数、交叉率和变异率 |
| `evaluations_per_run` | 每次运行的目标函数评价次数 |
| `source_sha256` | 源数据文件校验值，用于确认数据版本 |
| `config_sha256` | 配置文件校验值，用于确认参数版本 |
| `minimum_path_share` | 每条启用路径的最低批次份额 |
| `objectives` | 两个优化目标的字段名 |

### `runs.csv`

每行对应一个独立算法运行，即一个案例、一个场景和一个随机种子的组合。主要字段包括运行时间、可行种群规模、非支配解数量、该次运行发现的最低成本、最短交付时间、标准化超体积和间距指标。

需要注意，`min_cost_usd` 和 `min_weighted_mean_delivery_time_h` 可能来自两个不同的非支配解。它们不能被拼接成一个实际运输方案。

### `fronts.csv`

保存每次独立运行最终得到的全部可行非支配目标点。每行包含案例、场景、随机种子、点编号、总成本和货量加权平均交付时间。

这个文件适合分析不同随机种子的前沿差异，或追踪某个种子下的非支配结果。

### `combined_pareto.csv`

把同一案例和场景下30次运行的非支配解汇总，再次删除被支配解，得到跨随机种子的非支配联合解集。论文中的成本与时间散点图以及门户激活分析主要基于这个联合解集。

`source_seeds` 表示某个目标点来自哪些随机种子。联合解集是既定搜索预算下发现的近似前沿，不代表已经证明全局最优。

### `aggregate.csv`

按案例和场景汇总30次运行，包含：

| 字段组 | 含义 |
| --- | --- |
| `runs`、`successful_runs`、`success_rate` | 运行数量和成功率 |
| `total_front_points`、`union_front_size` | 30次运行产生的点数及联合解集大小 |
| `best_cost_usd`、`cost_median_usd` | 各次运行最低成本的最好值和中位数 |
| `best_weighted_mean_delivery_time_h`、对应中位数 | 各次运行最短交付时间的最好值和中位数 |
| 四分位数字段 | 不同随机种子间的分布范围 |
| `hypervolume_*`、`spacing_*` | 算法获得的非支配解集质量指标 |
| `elapsed_*` | 计算时间 |

`cost_median_usd` 是30个“每次运行最低成本”的中位数。交付时间中位数采用相同逻辑。两个中位数不一定对应同一个解。

### `representative_solutions.csv`

保存联合解集中的方案信息，并标记具有代表性的解。常见角色包括最低成本解、平衡解和最短交付时间解。文件还记录方案的总成本、加权平均交付时间、最大运输时间、延期量和路径分配数量。

如果要回答“某个场景下选哪一个方案进行展示”，应先从这里选择代表解。

### `representative_allocations.csv`

给出方案内部的货物分配。每行记录方案编号、货物批次、分配货量和路径所经过的弧段。门户份额和具体运输路径均可从这里追踪。

如果要回答“某批货物为什么经过某个门户”或“一个代表解如何分配货量”，需要同时使用 `representative_solutions.csv` 和本文件。

## 6. `analysis/` 中各文件的作用

`analysis/v06_threshold_scenarios/`、`analysis/v07_activation_scenarios/` 和 `analysis/v08_focused_activation_thresholds/` 分别对应三轮主要阈值实验。

### `scenario_effects.csv`

这是查看成本和交付时间变化的首选文件。每行对应一个案例和场景，提供：

| 字段 | 含义 |
| --- | --- |
| `cost_median_usd` | 30次运行最低成本的中位数 |
| `cost_change_pct_vs_baseline` | 相对于同版本基准的成本中位数变化百分比 |
| `weighted_mean_delivery_time_median_h` | 30次运行最短加权平均交付时间的中位数 |
| `delivery_time_change_h_vs_baseline` | 相对于同版本基准的时间中位数变化 |
| `union_front_size` | 跨种子非支配联合解数量 |

这个文件适合回答“某个中断场景使成本和时间变化了多少”。它不直接提供每个方案的门户份额。

### `gateway_shares.csv`

保存代表性方案的门户份额。主要字段包括洛杉矶/长滩、西雅图/塔科马、纽约/新泽西的货量占比，以及方案中的最小路径份额。

这个文件适合回答“最低成本解、平衡解或最短时间解分别使用了哪些门户”。它不代表联合解集中所有解的完整分布。

### `ny_activation.csv`

这是判断纽约/新泽西是否激活的核心文件。主要字段含义如下：

| 字段 | 含义 |
| --- | --- |
| `union_solutions` | 联合解集中的解数量 |
| `ny_nj_using_solutions` | 纽约/新泽西份额大于零的解数量 |
| `ny_nj_activation_pct` | 使用纽约/新泽西的解占联合解集的比例 |
| `ny_nj_share_min_pct_when_used` | 在正份额解中的最小份额 |
| `ny_nj_share_mean_pct_when_used` | 在正份额解中的平均份额 |
| `ny_nj_share_max_pct_when_used` | 在正份额解中的最大份额 |

最后三个份额字段只统计使用纽约/新泽西的解。如果只有部分解使用该门户，`mean_pct_when_used` 是条件平均值，不能当作整个联合解集的平均份额。

判断“稳定达到10%”时，需要同时满足两个条件：所有联合解都使用纽约/新泽西，并且最小份额达到10%。只看平均份额可能会掩盖部分解仍低于10%的情况。

### `paired_statistics.csv`

汇总同随机种子的场景与基准配对结果。统计对象只有最低成本和最短货量加权平均交付时间。文件包含配对差值的均值、中位数、百分比变化、bootstrap置信区间、精确符号检验、Holm校正p值和配对Cohen's d_z。

这个文件适合回答“成本或时间变化是否在30个随机种子下保持相同方向”。它不能用于宣称门户份额通过了配对显著性检验。

### `paired_differences.csv`

保存每个随机种子的具体配对差值。它用于检查异常种子、确认差值方向和重新核对汇总统计。出现统计结果疑问时，应从这个文件追踪到单次运行。

### `paired_statistics_manifest.json`

说明配对统计采用的方法，包括配对键、指标、bootstrap次数、置信区间类型、符号检验、Holm校正方式和随机数生成规则。

### 目录中的SVG图

`scenario_cost_change.svg` 展示各场景相对于基准的成本变化。`scenario_time_change.svg` 展示交付时间变化。`balanced_gateway_shares.svg` 展示平衡代表解的门户份额。这些是各轮分析自动生成的检查图，适合快速核对，但论文整合图位于 `paper/figures/`。

## 7. 场景名称怎么读

| 名称形式 | 含义 |
| --- | --- |
| `pilot_baseline` | 基准场景 |
| `uswc_port_capacity_60pct` | 两个西海岸门户的剩余容量为60% |
| `la_lb_port_capacity_50pct` | 洛杉矶/长滩剩余容量为50% |
| `seattle_tacoma_port_capacity_50pct` | 西雅图/塔科马剩余容量为50% |
| `uswc_departure_delay_168h` | 西海岸海运服务增加168小时班次延误 |
| `uswc_compound_30pct_delay_168h` | 西海岸剩余容量30%，并增加168小时班次延误 |

场景名称中的 `pct` 表示剩余容量，不是容量损失比例。例如，`30pct` 表示剩余30%，即下降70%。

## 9. 建议的数据读取顺序

如果需要快速理解一轮实验，可按以下顺序读取：

1. 打开该结果目录中的 `manifest.json`，确认案例、场景、种子和计算预算。
2. 查看对应分析目录中的 `scenario_effects.csv`，了解成本和时间变化。
3. 查看 `ny_activation.csv`，判断纽约/新泽西是否被使用以及份额是否达到10%。
4. 查看 `gateway_shares.csv`，了解代表解的具体门户构成。
5. 查看 `paired_statistics.csv`，确认成本和时间变化在随机种子间是否一致。
6. 如果汇总结果存在疑问，使用 `paired_differences.csv`、`fronts.csv` 和 `representative_allocations.csv` 追踪具体运行和路径。

## 10. 结果解释边界

读取或引用这些结果时，应遵守以下规则：

1. 纽约/新泽西份额是模型结果，不是优化目标。
2. 网络总货量10%判据与单批次最小路径份额约束不能混用。
3. 离散测试只能给出激活区间，不能声称已经得到精确连续阈值。
4. D2的复合场景结果不单调，应解释为过渡区域。
5. 门户份额目前是联合解集的描述性结果，没有进行与成本和时间相同的配对显著性检验。
6. 各实验版本必须使用其目录内的基准进行比较。
7. 不应把分别标准化的超体积数值直接当作不同场景之间的效应大小。
8. 小幅负成本变化可能来自随机搜索差异，不能直接解释为中断改善成本。
9. 成本和交付时间的运行级最优值可能来自不同解，不能组合成一个不存在的运输方案。
10. 现有结果说明替代门户在严重中断下保留了可行运输选择，但没有通过关闭该门户的反事实实验识别其净收益。
